## 代码审查 + 多 Agent 虚拟 API 改造

**结论**：改造前的 `stats_proxy.py` 是单端口共享网关，所有调用方共用 `api_token`、
模型注册表、语义安全会话字典与 8 个推理槽；`resolve_model()` 会把任意 `model`
静默改写为当前加载模型。多 Agent 并并发会串扰（隔离误伤、槽位抢占、usage 混账），
且响应 `model` 回显别名造成模型身份幻觉 → 判定为**不支持多用户共用**。

**实现**（`Sources/AiguruBootCore/Resources/stats_proxy.py`）：
- 新增 `VirtualApi` / `VirtualApiRegistry`：`/v1/a/<id>/...` 虚拟 base path，每 Agent
  独立 `api_key`（token_urlsafe(32)、compare_digest）、模型别名映射、并发配额
  （BoundedSemaphore，`handle_one_request` 的 finally 归还）、用量按 `vapi_id` 分区。
- 会议键强制前缀 `<vapi_id>:`；`SemanticSecurityGuard` 加 TTL/条数上限。
- `/v1/models` 与响应 `model` 回填真实模型 id；新增响应头
  `X-Aiguru-Virtual-API` / `X-Aiguru-Actual-Model` / `X-Aiguru-Virtual-Model`。
- 管理端点 `/v1/vapis`（列表/详情/usage/签发/轮换/撤销/开关），control token 保护；
  注册表 0600 原子落盘 `credentials/virtual-apis.json`。
- `legacy` 共享端点保留旧客户端兼容；`--vapi-strict 1` 可关闭回环匿名回落。
- 收口两个越权面：`/api/` 引擎管理面虚拟身份 403、LAN 全禁、强隔离/有控制凭据时要求
  control token；安装提案创建纳入鉴权，新增 `valid_installation_artifact` 与每 IP 10/60s 限速。
- 修复 HTTP/1.1 keep-alive 定界（chunked POST 拒绝、流结束关闭连接）。

**宿主侧**：`LlmBackend.swift` 增加 `virtualApisFileURL` / `strictVirtualApis`；
`LlmCore.swift` 启动参数加 `--vapi-file` / `--vapi-strict`；`LlmRootView.swift` 增加
「多 Agent 虚拟 API」设置卡片。文档更新 `Docs/AgentApi.md`、`Docs/Architecture.md`。

**验证**：`python3 -m unittest discover -s Tests/GatewayTests` → 94/94 通过
（原 73 + 新增 21，含 `Tests/GatewayTests/test_virtual_api.py`）。Swift 三个改动文件
`swiftc -frontend -parse` 语法通过。

**环境注意**：`swift test` 需要 `TMPDIR=/tmp swift test --disable-sandbox
--scratch-path /tmp/aiguru-swift-build`；WorkBuddy 沙箱拦截 `~/Library/Application
Support/AiguruBoot/` 下的测试文件删除，导致 63 项中 11 项环境污染型失败。另有 2 项
真实既有漂移：`MOSSImage内置目录` / `VLXSeek内置目录与视觉能力` 的
`requiresManualImport` 与 `localDirectoryRequirements` 断言与 `models.json` 不一致，
与本次改动无关，待本地复验处理。

**审查报告要点**（只读子代理产出）：P0 = `/api/` 管理面直通（已收口）、安装提案绕过鉴权
（已修）、HTTP/1.1 定界（已修）；P1 未修 = `LlmCore` 停止→启动竞态、误杀无关 MLX 进程、
安装服务硬编码 0.0.0.0、control token 绕过审批、Anthropic 多模态 content 结构、
集群 base_url link-local 与 token 外泄、下载器 206/staging、Bonjour didRemove。

## 第三轮：Agent 凭证 Tab + 真实 token 管理

**需求**：增加设置 Tab，设计真实 token 管理，为接入的 Agent 提供凭证。

**安全设计（关键决策）**：把虚拟 API 的明文 `key` 存储改为 **只存 SHA-256 `key_hash` + 6 位 `key_prefix`**。
`VirtualApi.matches_key` 用 `compare_digest(hash_credential(cred), key_hash)`；`VirtualApiRegistry.by_key`
改为 `by_hash`；`_load()` 遇到旧版含 `key` 的注册表立即迁移并回写。明文只在
`POST /v1/vapis`（201）与 `/rotate` 响应里返回一次，服务端无法再次读出 → **丢失只能轮换**。
新增 `hash_credential` / `validate_vapi_models` / `usage_summary_by_vapi`（单次遍历聚合）。

**修复的真实缺陷**：`_begin_request` 原先会对管理路径做虚拟身份解析，强隔离模式下带 control
token 的 `/v1/vapis` 被当成匿名推理返回 401，凭证页会完全失效 → 管理路径跳过 vapi 解析，
由 `_authorize_vapi_management` 单独鉴权，且不占用推理并发槽。`_release_vapi_slot` 改绑
获取瞬间的 semaphore 对象，使 `update()` 调整 `max_concurrent` 时不会让在途请求把配额归还到
新槽。`LlmCore.gatewayArgs` 现在**始终**传 `--control-token-file`（不再只在 LAN+远程部署时），
管理面始终受凭据保护；对应把 `/api/*` 管理面的 control token 条件收敛为只看
`registry.strict`，避免常驻 control token 破坏本机 Ollama CLI 的 `/api/pull`。

**新增管理端点**：`GET /v1/vapis` 额外返回 `available_models` 与 `usage_24h`；
`GET /v1/vapis/<id>/connection`（接入契约，不含明文）；`POST /v1/vapis/<id>/update`
（改 label/models/配额/开关，不动凭据）；create 响应内嵌 `connection`。
`_authorize_vapi_management` 增加未登记 `Origin` 拒绝（403），防本机网页 CSRF 签发密钥。

**Swift 宿主**：新增 `AgentCredentialStore.swift`（@MainActor ObservableObject，control token
鉴权 HTTP 客户端 + Codable 模型 + 表单草稿校验）与 `AgentCredentialsView.swift`
（凭证卡片、新建/编辑表单、一次性密钥窗口、接入配置复制、端点详情 sheet、强隔离开关）。
`LlmRootView` 新增 `ContentTab.credentials`（「凭证」，`key.fill`），局域网卡片加跳转按钮；
`LlmBackend` 新增 `static gatewayPort`。**刻意不做后台轮询**：轮询占用 isBusy 会让用户的
轮换/撤销操作被静默跳过，改为进入页面 + 操作后刷新。

**验证**：网关 unittest **115/115 通过**（新增 `test_credential_management.py` 9 项：哈希落盘、
旧注册表迁移、control token/Origin 鉴权、strict 下管理面可用、签发→调用→轮换→编辑→启停→
撤销全生命周期、用量归因）。`swift build` 通过；Swift `swift test` 70 项中新增
`AgentCredentialTests` 5 项全通过，其余 10 个 issue 仍为沙箱环境污染。
文档同步 `Docs/AgentApi.md`（桌面端凭证页、管理端点表、哈希策略、常驻 control token）
与 `Docs/Architecture.md`。
